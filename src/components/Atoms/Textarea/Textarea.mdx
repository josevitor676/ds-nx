## Como usar?

- **Comentários e Feedbacks:** Onde o usuário precisa expressar opiniões detalhadas.
- **Descrições de Items:** Cadastro de produtos ou perfis que exigem um resumo biográfico.
- **Mensagens de Suporte:** Para descrever problemas em tickets de atendimento.

## Como não usar?

- **Dados Curtos:** Para nomes, e-mails, senhas ou endereços curtos, utilize o Input de texto simples.
- **Busca:** Campos de pesquisa devem ser sempre de linha única.
- **Formatos Rígidos:** Se o texto precisar de negrito, itálico ou listas, use um editor Rich Text em vez do Text Area comum.

## Boas práticas

### ✅ Quando usar

- **Comentários e feedbacks** — onde o usuário precisa expressar opiniões detalhadas.
- **Descrições de itens** — cadastro de produtos ou perfis que exigem um resumo biográfico.
- **Mensagens de suporte** — para descrever problemas em tickets de atendimento.

### ❌ Quando não usar

- **Dados curtos** — para nomes, e-mails, senhas ou endereços, use o **Input** de texto simples.
- **Busca** — campos de pesquisa devem ser sempre de linha única.
- **Formatos ricos** — se o texto precisar de negrito, itálico ou listas, use um componente de **Rich Text Editor**.

## Acessibilidade

- ⌨️ Totalmente navegável por teclado; o elemento nativo `<textarea>` é focável por Tab.
- 🔊 Use `aria-describedby` apontando para o `helperText` quando ele comunicar um erro ou instrução crítica.
- 🔒 O atributo `disabled` bloqueia a interação e é comunicado a tecnologias assistivas nativamente.
